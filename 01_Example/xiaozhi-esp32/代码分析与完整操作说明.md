# ESP32-S3-PhotoPainter 代码分析与完整操作说明

适用目录：`E:\ESP32\ESP32-S3-PhotoPainter\ESP32-S3-PhotoPainter-main\01_Example\xiaozhi-esp32`。分析日期：2026 年 10 月 17 日。

这是一套以小智 ESP32 为基础、面向六色电子纸相框的 ESP-IDF C/C++ 工程。程序提供基础相册、网络上传、AI 对话三种工作模式，并通过独立的模式选择程序切换。三种模式在启动时择一运行，不能同时把设备当作网络上传服务器和 AI 语音终端。

本文覆盖本目录实际接入的功能、配套 SD 卡网页、配置方式、运行链路和操作限制。源码分析不等于硬件实测；本文的功能分析以源码为依据；此次天气及生图变更已通过 ESP-IDF 5.5.2 完整编译，未烧录、连接实物或调用付费生图服务。工程包含大量其他开发板和第三方依赖，不能把它们的功能当成此相框已经启用的功能。

官方参考：[微雪 ESP32-S3-PhotoPainter 使用说明](https://docs.waveshare.net/ESP32-S3-PhotoPainter/Instructions-For-Use/)。官网介绍三种模式、按键及首次联网绑定流程；下文的具体行为主要由本地源码确定。官网和本地版本不同之处见第 2 节。

官网是操作参考，但不能替代本目录的具体实现。以下官网概述均对应[官方使用说明](https://docs.waveshare.net/ESP32-S3-PhotoPainter/Instructions-For-Use/)，本地行为的依据列在末列。

| 项目 | 官网概述 | 本地源码行为 | 核对位置 |
| --- | --- | --- | --- |
| 初始模式 | 默认 AI 模式 | NVS 中没有 `PhotPainterMode` 时写入 `1`，即基础模式；已有记录时沿用记录 | `main/main.cc` |

| 图片评分 | 评分及重置评分 | 当前板级 MCP 注册中没有评分工具；仅残留未使用的 `sdcard_score` 变量 | 板级 `InitializeTools`、`xiaozhi_mode.cpp` |
| AI 轮播 | 评分后约 30 分钟轮播 | 通过工具显式开启，默认 1 分钟；可按分钟或小时设置 | `xiaozhi_mode.cpp` |
| 网络上传 | 主要描述热点连接 | 同时实现 AP 和 STA 两种联网方式 | `Network_mode.cpp`、配套网页 |
| PWR 睡眠 | 开机后单击进入睡眠 | 软件只产生 `PWRButtonGroups` 事件，未找到消费任务；不能据此确认软件休眠已实现 | `button_bsp.c` |

因此，应区分“出厂固件的行为”“当前目录源码的行为”“已经烧入设备的固件行为”。重新烧录应用但保留 NVS，也不一定回到源码的初始模式。

## 3 SD 卡准备与配置

### 3.1 复制配套资源

本地配套资源目录为：

`E:\ESP32\ESP32-S3-PhotoPainter\ESP32-S3-PhotoPainter-main\02_SDCARD`

将这个目录**里面的六个子目录**复制到 SD 卡根目录，而不是把 `02_SDCARD` 整个包一层复制进去。固件将卡挂载为 `/sdcard`。

| 卡根目录中的目录 | 用途与重要文件 |
| --- | --- |
| `01_sys_init_img` | 天气背景 `00_init.bmp` 和天气图标 |
| `02_sys_ap_img` | 网页上传结果 `user_send.bmp`，后续上传覆盖 |
| `03_sys_ap_html` | `index.html`、JavaScript、CSS、占位图，提供网络模式网页 |
| `04_sys_ai_img` | 生图结果 `sys_ai.jpg`，后续生成覆盖 |
| `05_user_ai_img` | AI 模式可按编号显示和轮播的本地图片 |
| `06_user_Foundation_img` | 基础模式相册、`config.txt`、运行时转换缓存 `sys_decode.bmp` |

源码路径使用 `06_user_foundation_img`，资源包名称使用 `06_user_Foundation_img`。本项目使用 FAT 挂载，通常不因大小写而区分目录；不要再建一个不同拼写的替代目录。移植到大小写敏感文件系统时需要统一。

SD 卡挂载失败会使 `User_Mode_init()` 返回 0，`app_main()` 随即返回，三种业务模式都不会启动。程序设置了 `format_if_mount_failed=false`，不会自动格式化损坏的卡。更换图片或配置时先停止设备运行并关机，更新后重新启动以重新扫描目录。

### 3.2 config.txt 的实际格式

文件虽然后缀为 `.txt`，内容必须是 JSON，不是 INI，也不是逐行 `key=value`。

```json
{
  "timer": 300,
  "ai_model": "doubao-seedream-5-0-flash-260915",
  "ai_url": "https://ark.cn-beijing.volces.com/api/v3/images/generations",
  "ai_key": "填写你自己的 API Key"
}
```

| 字段 | 作用 | 本地读取规则 |
| --- | --- | --- |
| `timer` | 基础模式深睡后的定时唤醒间隔，单位秒 | 转成整数后不得为 0；实际应填写正整数 |
| `ai_model` | 生图请求的模型字段 | 必须存在字符串；只填产品展示名称不一定可用 |
| `ai_url` | 生图 API 完整地址 | 必须存在字符串 |
| `ai_key` | 生图请求的 Bearer 凭据 | 必须存在字符串 |

本地配套文件的 `timer` 是 **300 秒，即 5 分钟**。基础模式代码的兜底值是 `13 * 60`，即 **780 秒**，旁边“60 秒”的注释不准确。只有完整配置读取成功，才会用 `timer` 覆盖兜底值。

同一个解析器被基础模式和 AI 模式复用，所以即使只想改相册定时，也应保留四个字段。基础模式读取失败会沿用兜底间隔；AI 模式读取失败则会提前退出相框 AI 扩展初始化，不能认为其图片、传感器和按键任务仍然正常。

配置读取缓冲区仅 1024 字节，底层读取没有容量参数，也没有为 JSON 显式追加结束符。操作上应保持配置简短、远小于 1024 字节，不写注释或长段说明；这只能降低风险，根本修复见第 18 节。文档不复制本地文件中的真实密钥。源码会把密钥输出到串口日志，分享日志前应删除该值。

## 4 全部按键与指示灯操作

### 4.1 按键规则

自定义按键驱动每 5 ms 扫描一次，消抖约 15 ms，长按阈值约 1 秒，单击与双击的区分窗口约 300 ms。选择模式时，多次“单击”应分开操作，听到提示后再按；快速双击 KEY 的回调是空的，不能当成两次模式选择。

| 按键与操作 | 生效条件 | 本地行为 |
| --- | --- | --- |
| PWR 单击开机、长按关机 | 硬件电源操作 | 官网定义的电源操作；软件没有给出完整的按键开关机时序 |
| PWR 开机后单击 | 任意模式 | 自定义驱动发出事件，但未接入软件休眠消费者；不要依赖它作为已验证的深睡入口 |
| KEY 长按 | 基础、网络或 AI 模式，系统已经运行 | 写入模式选择状态并重启，播放模式选择提示 |
| KEY 单击 | 模式选择状态 | 候选模式按 1→2→3→1 循环，语音提示 |
| KEY 再次长按 | 已至少选过一次候选模式 | 保存候选模式，重启进入对应模式 |
| KEY 长按但没有先单击选择 | 刚进入模式选择状态 | `Mode=0`，不会确认进入任何业务模式 |
| KEY 单击 | 基础模式深睡 | 唤醒但不自动切图 |
| KEY 单击 | 网络模式深睡 | 唤醒；AP 情况下清除初始自动休眠计数条件 |
| KEY 单击 | AI 模式处于 idle | 调用 `WakeWordInvoke("你好小智")`，启动对话 |
| KEY 单击 | AI 正在 listening 或 speaking | 该自定义任务没有对应操作 |
| BOOT 单击 | 基础模式运行中 | 显示下一张本地图片，然后请求深睡 |
| BOOT 按下唤醒 | 基础模式深睡 | 唤醒后合成一次单击事件，自动切图 |
| BOOT 长按 | 基础模式 | 设置定时及 KEY/BOOT 唤醒源，松开 BOOT 后深睡 |
| BOOT 长按 | 网络模式 | 关闭 Wi-Fi，进入深睡，设置 KEY 和 30 秒定时唤醒 |
| BOOT 单击 | 网络 STA 初始化失败的恢复路径 | 保存 AP 模式并重启；并非正常联网状态下的通用切换键 |
| BOOT 单击 | AI 模式 | 设置 `wifi.force_ap=1`，约 1 秒后重启进入配网 |
| BOOT 长按 | AI 模式 | 根据聊天状态停止监听或打断播报、尝试结束对话；**没有调用深睡函数** |
| BOOT 双击 | 公共任务已初始化且屏幕锁可用 | 在电子纸显示充电状态、电池电压和百分比 |
| BOOT 配合启动 | 芯片下载流程 | BOOT 兼作下载引脚；正常运行时的单击不等于进入烧录模式 |

AI 模式还用小智 `Button` 类监听 BOOT，与自定义多击驱动同时存在。因此双击等复杂手势是否额外触发配网，应上板确认；不要把“公共双击显示电量”理解为 AI 模式下没有任何竞争的保证。

### 4.2 指示灯

| 源码名称 | GPIO | 主要用途 |
| --- | --- | --- |
| `LED_PIN_Green` | 42 | 刷屏时约 100 ms 亮灭交替，完成后停止 |
| `LED_PIN_Red` | 45 | 基础/网络初始化状态、网络传输闪烁、AI listening/speaking 与 idle 状态切换 |

两路 LED 均低电平点亮。官网按面板标识称 ACT/PWR，代码按颜色称 Green/Red，具体丝印对应关系以实物为准。刷屏期间等待指示结束再操作，避免互斥锁超时或事件被合并。

## 5 首次开机与模式切换

1. 准备完整 SD 卡目录及合法配置文件，插卡后开机。
2. 本源码在模式记录为空时进入基础模式，因此首次开机没有配网语音并不一定是故障。
3. 长按 KEY 约 1 秒，设备会重启到模式选择程序。
4. 单击 KEY 一次选基础模式、分开单击两次选网络模式、分开单击三次选 AI 模式，以语音提示为准。
5. 再长按 KEY 确认，设备保存模式并重启。
6. 要使用 AI 或网络 STA，先进入 AI 模式完成配网。连接设备的 `Xiaozhi-xxxx` 热点，浏览器打开 `http://192.168.4.1`，选择可用 Wi-Fi 并输入密码。随后按设备激活提示，在[小智控制台](https://xiaozhi.me)绑定设备；这是官网给出的绑定入口，具体界面以服务当前状态为准。

`Xiaozhi-xxxx` 用于 AI 配网；`esp_network` 用于模式 2 的照片上传。这是两套不同的热点和网页。

AI 网络启动先查看已保存的 SSID；没有记录时直接配网，有记录但约 60 秒仍未连上也会回退配网。AI 模式单击 BOOT 可以主动重新配网；它主要设置强制配网标志，不是清空整个设备 NVS。

## 6 基础模式完整操作

### 6.1 添加和切换图片

1. 将图片放入 `06_user_Foundation_img` 目录的第一层，子目录不会递归扫描。
2. 推荐使用 800×480 横图或 480×800 竖图。当前路径支持 `.bmp`、`.jpg`、`.png` 及全大写扩展名；不包含 `.jpeg`，也不应依赖混合大小写扩展名。
3. BMP 使用 24 位、未压缩格式。JPG/PNG 由相应解码库处理，并非所有罕见编码变体都保证可用。
4. 重启进入基础模式，单击 BOOT 显示下一张。
5. 刷图任务结束后自动请求深度睡眠；BOOT 唤醒会切换下一张，KEY 唤醒只恢复运行。

冷启动和 KEY 唤醒并没有自动发出切图事件，电子纸可能仍保持此前的画面。它保留画面不代表程序没有启动。

相册顺序来自 `readdir()` 的扫描顺序，代码没有按文件名排序；“第 1 张”不能保证就是字母或数字排序第一的文件。完整固件路径含结束符必须小于 80 字节，过长文件名会被跳过。

### 6.2 定时换图

`config.txt` 中 `timer=300` 表示**进入深睡后约 300 秒唤醒**，不保证两次刷屏开始时间严格相隔 300 秒，因为启动、读卡、解码和刷屏也需要时间。

计时唤醒会合成 BOOT 单击，按顺序显示下一张并再次休眠。相册计数 `sdcard_Basic_count` 使用 `RTC_DATA_ATTR`，可跨深睡保留；普通断电、复位或模式切换不应依赖其继续保持。

KEY 唤醒后没有自动再次休眠的通用空闲计时器。需要继续省电时，可单击 BOOT 换图，或长按 BOOT 主动睡眠。

相册为空时存在拿到屏幕互斥锁但未释放的代码路径。使用时至少放入一张有效图片；若已经出现后续刷屏无响应，补图后重启，软件修复位置见第 18 节。

## 7 网络服务器模式完整操作

### 7.1 AP 热点上传

1. 切换模式 2。
2. 手机或电脑连接热点 `esp_network`，密码 `1234567890`。
3. 浏览器打开 `http://192.168.4.1/index.html`。建议明确写出 `index.html`；此服务器未实现根路径自动跳转，也未实现自动弹出门户。
4. 点击 **Input** 选择浏览器可解码的图片。
5. 等待右侧 **Processed image** 出现处理结果。网页按横竖方向拉伸到 800×480 或 480×800，再转换为六色。
6. 用 **Rotate** 每次旋转 90°，循环 0°、90°、180°、270°。
7. 暂时保留 **NetworkMode: AP**，点击 **Send**。
8. 上传成功提示只表示服务器收到了规定长度的数据；等待电子纸实际完成刷新再断开连接或继续上传。

网页不保持原图比例，也没有交互式裁剪框。要避免人物变形，先自行裁成 5:3 横图或 3:5 竖图。网页上传覆盖 `02_sys_ap_img/user_send.bmp`，不会自动添加到基础相册或 AI 相册。

### 7.2 STA 局域网上传

STA 的含义是相框连接现有路由器，与手机或电脑处于同一个局域网。

1. 先在模式 3 完成联网，让设备保存 Wi-Fi 凭据。
2. 回到模式 2 的 AP 网页，选择一张图片，选择 **STA**，再点 **Send**。
3. 等待图片刷新完成后重启设备。只点击 STA 按钮不会单独保存设置；模式字节随图片上传，固件在处理刷图事件后才写入 NVS。
4. 手机或电脑连接同一路由器，打开 `http://esp32-s3-photopainter.local/index.html`。
5. 如果系统不支持 mDNS 或无法解析 `.local`，从路由器查看设备 IP，再访问 `http://设备IP/index.html`。
6. 要返回 AP，在网页选择 AP 并随图片发送，等刷新结束后重启。

STA 直接从 `nvs.net80211` 的 `sta.ssid` 和 `sta.pswd` 读取底层 Wi-Fi 数据，并非调用小智 SSID 列表管理器。它依赖底层 NVS 数据布局，且启动等待 IP 只有 8 秒。没有有效凭据或超时会进入恢复分支，此时单击 BOOT 可回 AP。

### 7.3 网络模式的睡眠

AP 初次启动时，如果没有连接事件，任务约计数 60 次、每次等待 500 ms 后进入深睡；深睡约 30 秒后重启再开热点。连接事件清除自动休眠条件。KEY 从深睡唤醒也清除此条件，便于连接。

AP 的断开回调直接触发休眠事件，没有统计“是否仍有其他客户端在线”。尽管热点最多允许 4 个连接，其中一个断开也可能导致其他客户端失去连接。STA 断线也会触发休眠路径；日志中的“trying to reconnect”不代表回调实际调用了重连。

长按 BOOT 可主动进入网络模式深睡。网络模式没有把 BOOT 设置成深睡唤醒引脚，应使用 KEY 或等待定时器。

### 7.4 HTTP 接口和上传格式

| 请求 | 返回或作用 |
| --- | --- |
| `GET /index.html` | 从 SD 卡读取网页 |
| `GET /bootstrap.min.css`、`styles.min.css` | 样式文件 |
| `GET /bootstrap.min.js`、`script.min.js` | 网页脚本 |
| `GET /placeholder.svg` | 占位图 |
| `GET /NetWorkStatus` | 文本 `0` 表示 AP，`1` 表示 STA |
| `POST /dataUP` | 接收一字节网络模式加 BMP 文件 |

上传体不是 JSON，也不是 multipart 表单，格式是：

```text
第 0 字节：0x00 为 AP，0x01 为 STA
第 1 字节起：完整 24 位未压缩 BMP，包含 BM 文件头
Content-Type: application/octet-stream
```

800×480 的 24 位 BMP 在此网页编码下大小为 1,152,054 字节，加模式字节后请求体为 1,152,055 字节。服务端每次最多读取 10 KiB 并追加到 SD 卡；成功判断主要是文件写入字节数匹配，不是图片内容的完整合法性校验。自行编写上传客户端时必须先生成正确尺寸和六色 BMP，不能把原始 JPEG 直接发给此接口。

## 8 AI 对话和全部板级 MCP 操作

### 8.1 对话

完成配网与激活后，唤醒词为“你好，小智”；处于 idle 时也可以单击 KEY 启动对话。音频由 ESP32 采集和播放，语音理解及回答依赖服务器；设备上没有本地运行完整大语言模型。

长按 BOOT 的任务名字含 `sleep`，但实际只是切换聊天状态、设置指示灯。不能据此认定麦克风系统断电、Wi-Fi 关闭或 ESP32 已经深睡。

### 8.2 九个板级工具

自然语言示例用于向服务端表达意图；是否触发工具取决于服务端模型和 MCP 配置。真正的设备能力以工具名和参数为准。

| 工具名 | 参数 | 操作示例与结果 |
| --- | --- | --- |
| `self.disp.refreshWeather` | 无 | “刷新天气”，后台联网获取并刷屏；取消开机自动刷新，失败后可再次请求 |
| `self.disp.SwitchPictures` | `value`，整数 1～启动时图片数量 | “显示第 2 张图片”，显示 `05_user_ai_img` 扫描列表对应图片，并退出轮播 |
| `self.disp.getNumberimages` | 无 | “相册里有几张图片”，统计当前内存链表，等待最多 2 秒 |
| `self.disp.aiIMG` | 无 | “帮我生成一张月球的图片”，以最近用户识别文本启动生图流程 |
| `self.disp.imgloop` | 无 | “开始轮播相册”，置位轮播事件 |
| `self.disp.imgloopEit` | 无 | “停止轮播”，清除轮播事件；名称里的 `Eit` 是源码原样拼写 |
| `self.disp.imgsetTimerloop min` | `timer`，整数 1～60 | “轮播间隔设为 10 分钟” |
| `self.disp.imgsetTimerloop h` | `timer`，整数 1～240 | “轮播间隔设为 2 小时” |
| `self.disp.isSHTC3` | 无 | “读取设备温湿度”，读取 SHTC3 并返回温度、湿度字符串 |

两个设置时间的工具名含空格，应按源码原样识别；不能擅自写成没有空格的另一个接口。平台是否接受这种名称需要实际联调。

### 8.3 轮播规则

默认 `img_loopTimer=60,000 ms`。开启后任务先等约 1 秒，再发出一次显示事件，然后按设定间隔等待。初始索引是图片总数，显示前递减，所以第一次轮播从扫描列表末尾开始，随后倒序循环。

时间设置只修改 RAM，没有写 NVS，重启后恢复默认 1 分钟。它也不同于 `config.txt` 的 `timer`：后者只控制基础模式睡眠唤醒。修改间隔不会中断当前已经开始的 `vTaskDelay()`，重新开启或停止轮播也可能受任务当前等待阶段影响。

主动指定图片或发起生图会清除轮播位。`getNumberimages` 只数已有链表，不重新读卡；运行中换文件不会自动更新编号和数量，更新卡内容后应重启。

### 8.4 通用工具与未接入能力

小智公共 MCP 另外注册 `self.get_device_status` 和 `self.audio_speaker.set_volume`，音量范围 0～100；例如“把音量设为 50”。状态数据实际包含音量和网络信息等，不保证含电池信息：本板未重写 `Board::GetBatteryLevel()`，电池信息显示走的是独立 PMIC 路径。

管理类 `userOnly` 工具包括 `self.get_system_info`、`self.reboot`、`self.upgrade_firmware(url)`，是否在控制端开放取决于工具发现过滤。它们不等同于所有日常语音对话都会暴露的功能。

本板没有接入相机、背光或 LVGL 主题显示对象。框架里虽然有拍照、亮度、主题、截图等代码，不能将这些当作此相框已有操作。当前也没有图片评分、评分清空、语音切换三种运行模式的板级工具。

## 9 AI 生图配置和工作过程

### 9.1 操作流程

1. 在所使用的生图服务中取得可用模型/接入点、API 地址和密钥，写入 `config.txt` 的三个 AI 字段。
2. 保留合法的正数 `timer`，保存后重新启动 AI 模式。
3. 确认设备已联网并完成小智激活。
4. 唤醒后明确描述需要生成的图片，如“帮我生成一张横向的月球基地插画”。
5. 等待服务返回、图片下载及电子纸刷新；工具描述已移除固定“10～20 秒”的耗时承诺。

当前代码请求生成接口超时为 **180 秒**，下载超时为 **60 秒**，最终还要加解码和刷屏时间。这是超时上限，不是正常耗时承诺。服务当前是否支持指定模型及参数，需要在使用该账号时核实；本文没有用本地密钥发起请求。

### 9.2 数据链路

```text
服务器 STT 用户文字
  → Display::SetChatMessage 的用户回调
  → str_ai_chat_buff 保存最近用户文本
  → 云端调用 self.disp.aiIMG
  → ai_IMG_Task 设置请求 JSON
  → HTTPS POST 生图接口
  → 取响应 data[0].url
  → GET 下载图片到 PSRAM
  → 覆盖 /sdcard/04_sys_ai_img/sys_ai.jpg
  → 发出电子纸事件
  → 解码、缩放、抖动、刷新
```

请求字段为 `model`、`prompt`、`response_format="url"`、`size="1280x720"`、`output_format="jpeg"`、`watermark=false`。认证头使用 `Authorization: Bearer ...`，TLS 使用编入工程的证书文件。

模型必须支持这些参数并返回 `data[0].url`；代码没有实现 base64 图片响应分支。请求显式指定 JPEG，下载内容以 `.jpg` 命名并按 JPG 解码。配套配置改为 Seedream 5.0 Flash 的 `doubao-seedream-5-0-flash-260915`；保留现有 URL 和密钥。

生图 HTTP 响应与下载共用约 700 KiB 缓冲区，超过容量会报错。生图成功只覆盖一个系统文件，不自动追加到 `05_user_ai_img`。需要长期收藏或轮播时，关机后将结果另存到 AI 相册，使用新的短文件名，再重启。

MCP 回调返回 `true` 表示已提交异步任务，不保证图片最终已生成或刷完。`is_ai_img` 主要在刷屏阶段置为忙，不能完整防止 HTTP 生成期间再次收到请求。

## 10 天气与温湿度

开机状态回调不再发起天气请求，也不触发天气刷屏。用户说“刷新天气”“更新天气”或“显示天气预报”时，通过 `self.disp.refreshWeather` 发出事件，GUI 后台任务请求源码写死的地址 `http://t.weather.sojson.com/api/weather/city/101280601`，解析 `data.forecast[0..3]`，将日期、温度、天气、风向和 AQI 合成到背景图上。

这不是 GPS 自动定位，也没有从 `config.txt` 读取城市。改变天气城市需要修改 `components/app_bsp/client_app.c` 的 `WEATHER_API_URL` 并重新编译。代码单次请求超时 10 秒，尝试次数常量是 1；没有每日定时更新任务。每次语音调用均可重新请求；请求或字段校验失败时保留当前画面。刷新天气会退出相册轮播。

天气页面依赖 `01_sys_init_img` 的背景和图标。设备能联网但天气没显示，应分别检查MCP 工具是否触发、HTTP 返回和图片资源。

温湿度则由 `self.disp.isSHTC3` 即时读本机 SHTC3 得到，和网络天气是两条独立数据链路。

## 12 启动流程与状态保存

```text

  → 默认事件循环
```

| 保存位置 | 字段或内容 | 生命周期 |
| --- | --- | --- |

## 13 FreeRTOS 任务与事件如何配合

| 任务或事件 | 作用 |
| --- | --- |
| 公共 KEY 任务 | 监听长按并请求进入模式选择 |
| 公共 BOOT 任务 | 监听双击，读取 PMIC 并显示电池信息 |
| Green/Red LED 任务 | 根据事件位和共享标志闪烁 |
| `Axp2101_isChargingTask` | 每约 20 秒记录充电状态、电压和电量 |
| 基础模式 BOOT 任务 | 获取当前节点，显示图片，递增索引，发出睡眠信号 |
| 基础模式睡眠任务 | 接收二值信号量，配置唤醒并深睡 |
| `Network_user_Task` | 响应连接、断开、传输及刷新事件 |
| `Network_sleep_Task` | 仅 AP 正常初始化时创建，处理初始无连接睡眠 |
| `gui_user_Task` | AI 模式统一处理天气、指定相册图、生图结果及轮播刷屏 |
| `ai_IMG_Task` | 执行生图 HTTP、返回图片数量、处理停止对话 |
| `ai_IMG_LoopTask` | 按间隔产生轮播刷屏事件 |
| `epaper_gui_semapHandle` | 所有这些显示路径共用的屏幕互斥锁 |

按键回调只设置事件位，耗时工作由任务执行。事件组不是消息队列：重复设置同一个位不会累积成多次操作。多个任务还共享图片索引、聊天缓冲区、忙状态等变量，快速连续命令不能保证逐条保存和执行。

多个 GUI 路径使用 `xSemaphoreTake(..., 2000)`，这里的 `2000` 是 FreeRTOS tick，不是显式转换后的 2000 毫秒。等待超时可能直接放弃已取出的显示事件。

## 14 图片从文件到电子纸的过程

### 14.1 三类路径

| 来源 | 前处理位置 | 最终显示入口 |
| --- | --- | --- |
| 基础/AI 本地图片、生图结果 | ESP32 解码、缩放、六色抖动并写临时 BMP | `EPD_SDcardScaleIMGShakingColor` |
| 网页上传 | 浏览器 Canvas 处理，生成 24 位六色 BMP | `EPD_SDcardBmpShakingColor` |
| 天气背景及图标 | 使用已准备好的 BMP 资源，再叠加文字 | `EPD_SDcardBmpShakingColor` 和绘字函数 |

带缩放入口先解码为 RGB888，再检查宽高是否大于 1350；任何一边超限就返回。因此大图可能先占用解码内存再被拒绝，不能把“自动缩放”理解成支持任意手机原图尺寸。

横图被拉伸到 800×480，竖图及正方形被拉伸到 480×800，使用最近邻缩放，不保持比例。随后用 Floyd–Steinberg 误差扩散将颜色压到黑、白、黄、红、蓝、绿六种纯色，误差按右侧 7/16、左下 3/16、下方 5/16、右下 1/16 传播。

处理结果写入 `06_user_foundation_img/sys_decode.bmp`，再由直接 BMP 路径装入帧缓冲。该缓存会被反复覆盖，并被相册扫描器主动排除。

直接 BMP 路径按 RGB 的精确值映射六色，其他颜色映射白色，本身没有进行误差扩散。这就是自行上传未经六色处理的 BMP 可能出现大面积白色的原因。

### 14.2 帧缓冲与刷新

800×480 共 384,000 像素。每个像素使用 4 bit 色码，一字节存两个像素，因此一个帧缓冲是 192,000 字节。代码同时分配原始和旋转帧缓冲，并分配 1,152,000 字节的 BMP RGB 缓冲；还要叠加解码图、缩放图、抖动临时内存及音频内存，PSRAM 是关键配置。

`EPD_Display()` 先旋转帧缓冲，再经 SPI 发送图像数据并触发刷新。实际刷新过程需要等待 BUSY，不是普通液晶的实时逐帧界面。代码中天气和相册走自定义电子纸驱动，小智框架的 `NoDisplay` 主要仍用于状态/文本回调；聊天文字并不会自动逐句显示成电子纸聊天界面。

## 15 音频和硬件连接

### 15.1 语音链路

```text
麦克风 → ES7210 → I²S → 音频前端/唤醒/编码
  → 网络 → 小智服务端识别、推理、工具决策
  → 返回音频 → 解码 → I²S → ES8311/功放 → 喇叭
```

板级输入输出采样率配置均为 24 kHz。`sdkconfig` 启用 AFE 唤醒、音频处理和设备端 AEC，唤醒模型为“你好小智”。`Application::Start()` 启动音频，联网，检查资源与固件版本/激活信息，再根据 OTA 配置选择 MQTT 或 WebSocket 协议并注册回调。

主要状态为 starting、wifi_configuring、activating、idle、connecting、listening、speaking、upgrading。idle 开启唤醒检测；识别唤醒后打开音频通道；云端返回语音时切 speaking；播报结束按监听模式回到 idle 或 listening。服务器 MCP 消息经协议层进入 `McpServer`，最终调用板级工具。

| 外设 | 源码 GPIO 或配置 |

| 电子纸 MOSI / SCLK / DC / CS / RST / BUSY | 11 / 10 / 8 / 9 / 12 / 13 |
| 电子纸 SPI | 40 MHz，半双工，片选由代码控制 |
| 共用 I²C SCL / SDA | 48 / 47 |
| AXP2101 | I²C 地址 `0x34` |
| SD CLK / CMD / D0 / D1 / D2 / D3 | 39 / 41 / 40 / 1 / 2 / 38，4 bit SDMMC |
| I²S MCLK / BCLK / WS | 14 / 15 / 16 |

AXP2101 初始化设置部分电源轨为 3.3 V，预充电 50 mA、恒流充电 500 mA、终止电流 25 mA。这里是代码寄存器配置，不能代替对实际电池与硬件电源设计的核对。

## 16 编译烧录与修改入口

### 16.1 当前构建配置

`sdkconfig` 指定 ESP32-S3、16 MB Flash、八线 PSRAM 80 MHz、中文以及 `CONFIG_BOARD_TYPE_ESP32S3_PhotoPaint=y`。现存 `build/project_description.json` 的工具路径指向本机 ESP-IDF 5.5.2，这只说明已有构建环境线索，不代表刚完成了重新编译。

分区表为 `partitions/v2/16m.csv`：NVS 位于 `0x9000`，两个 OTA 应用槽各 `0x3f0000`，第一槽从 `0x20000` 开始，assets 从 `0x800000` 开始占 8 MiB。Flash assets 和 SD 卡的六个目录用途不同，不能互相替代。

### 16.2 常用开发操作

在已经激活 ESP-IDF 的 PowerShell 终端执行，串口号替换为实际值：

```powershell
Set-Location 'E:\ESP32\ESP32-S3-PhotoPainter\ESP32-S3-PhotoPainter-main\01_Example\xiaozhi-esp32'
idf.py menuconfig
idf.py build
idf.py -p COM5 flash monitor
```

已有 `sdkconfig` 就先保留，检查板型和 PSRAM。更换芯片目标时才考虑 `idf.py set-target esp32s3`，并先备份配置。串口监视通常用 `Ctrl+]` 退出。串口和下载模式操作需结合实际 USB 连接；若需 BOOT 下载流程，参考官方站点的烧录说明，不把应用运行时 BOOT 单击当作下载动作。

擦除 Flash/NVS 会影响模式、Wi-Fi 和设备身份等记录，不是普通更新固件必需步骤。OTA 会替换运行固件，更新后应重新核对是否仍含 PhotoPainter 定制功能。本文没有执行任何烧录或擦除。

| 生图尺寸与超时 | `ai_app.cpp` 的 JSON 字段及超时常量 |
| 天气地址 | `client_app.c` 的 `WEATHER_API_URL` |
| 增加语音工具 | 板级 `esp32-s3-PhotoPainter.cc` 的 `InitializeTools()` |
| 显示行为 | `display_bsp.cpp`、`imgdecode_app.cpp` |
| 网页布局与旋转/上传 | SD 卡 `03_sys_ap_html/index.html`、`script.min.js` |
| 按键阈值与映射 | `button_bsp.c`、`src/multi_button/multi_button.h` |

只改 SD 卡网页或配置通常不需要重编译固件；修改 C/C++ 和编译配置则需要编译并更新设备。

## 17 常见问题排查

| 现象 | 优先检查 |
| --- | --- |
| 开机没有配网提示 | 是否仍在默认基础模式；用 KEY 切到模式 3 |
| 所有模式都不工作 | SD 挂载是否成功、资源是否多包了一层目录、电源是否正常 |
| KEY 两下没选到模式 2 | 是否被识别为无功能的双击；分开单击并听语音 |
| 只输入设备 IP 打不开上传页 | 加上 `/index.html`，使用 HTTP；确认连的是 `esp_network` |
| 网页空白或资源请求异常 | `03_sys_ap_html` 文件是否齐全，特别是 JS/CSS；资源缺失还有底层读取风险 |
| 上传成功但仍是旧图 | 等待刷屏；核对 BMP 数据和尺寸，查看屏幕锁/解码日志 |
| 选了 STA，重启仍是 AP | 是否真正发送了图片、是否等刷屏结束后才重启 |
| STA 启动后无法访问 | 先在 AI 模式联网；检查路由器、8 秒超时、mDNS；失败恢复分支可单击 BOOT 回 AP |
| 连接热点后偶尔掉线 | 可能是另一个客户端断开触发整体休眠；测试时只保留一个客户端 |
| 本地相册数量少 | 扩展名、子目录、文件路径长度；检查是否未重启重新扫描 |
| “第 1 张”与文件名不一致 | 没有文件名排序，按实际扫描顺序编号 |
| JPG/PNG 没显示 | 任一边是否超过 1350、解码是否成功、PSRAM 和 SD 写入是否正常 |
| 图片变形或方向不理想 | 自动处理是拉伸；先裁到目标比例，网页再检查 Rotate |
| 生图失败 | 四字段配置、模型和请求参数、网络、证书、HTTP 状态、700 KiB 缓冲限制 |
| 生图后相册数量不增加 | 生图只保存固定系统文件，需手动归档到 AI 相册后重启 |
| 轮播不按新间隔立即更新 | 当前延时尚未结束；设置只对后续等待生效，重启会复原 |
| 天气不更新 | 现在必须说“刷新天气”触发；没有开机或周期天气请求，失败可重试 |
| AI 长按 BOOT 后仍耗电 | 该路径结束对话，不执行深睡 |
| 电量语音查询没有结果 | 通用设备状态没有接入本板电池接口；公共双击显示读取独立 PMIC |
| 基础模式空相册后操作无效 | 屏幕锁可能未释放；补入有效图后重启，随后修复锁路径 |

## 18 静态代码分析发现的限制与风险

以下是源码可见的问题及其影响，不代表每项都已在实物复现。天气刷新已改为 MCP 手动触发，并增加返回字段校验；其余列出的历史问题未在本次变更中修复。

| 问题 | 代码依据 | 影响及后续处理方向 |
| --- | --- | --- |
| 空相册遗漏解锁 | `Basic_mode.cpp` 获取屏幕锁后，只有节点非空分支释放 | 后续显示超时；所有退出路径应释放锁 |
| 休眠信号顺序存在竞争 | 基础模式先 `xSemaphoreGive(sleep_Semp)`，后写 `Basic_sleep_arg=1` | 睡眠任务可能先读到旧值；应先设置状态再发信号 |
| 配置读取无容量保护 | `ai_app.cpp` 分配 1024 字节，`SDPort_ReadFile` 按实际文件长度读取 | 大配置可越界；应传容量、限制长度并追加结束符 |
| 用户识别文本无长度检查 | `xiaozhi_ai_Message` 用 `strcpy` 写 1024 字节缓冲区 | 长文本可能越界；应使用有界复制并约束请求长度 |
| HTTP 读取返回类型不合适 | `receive_data_redirect_handler` 用 `size_t ret` 接收可能为负的返回值 | 非超时错误可能绕过 `<=0` 分支并污染长度计算；应使用有符号类型 |
| 资源读取错误被当作长度 | `SDPort_ReadOffset` 返回 ESP 错误码，静态资源处理按 `size_t` 判断非零 | 缺文件时可能发送非预期内存数据；应分离错误状态和字节数 |
| 上传内容验证不足 | 上传成功只检查写入长度，直接 BMP 读取缺少完整尺寸/容量验证 | 自定义或损坏上传可能越界；应校验头、尺寸、长度和最大容量 |
| 忙状态覆盖不完整 | `is_ai_img` 在 GUI 刷屏阶段设置，HTTP 生图阶段仍可接收触发 | 连续生成命令可能合并或共享文本覆盖；应使用请求队列和完整忙状态 |
| BOOT 双重监听 | 板类 `Button` 与公共 `multi_button` 同时使用 GPIO0 | AI 双击/长按组合行为需要实测和统一映射 |
| AP 睡眠不统计在线数 | 任一 `AP_STADISCONNECTED` 直接置休眠位 | 一个客户端退出可中断其他客户端 |
| STA 读私有 NVS 格式 | `TraverseNvs` 解析 `nvs.net80211` blob | 依赖 SDK 内部存储方式，升级 SDK 后应验证兼容性 |
| 密钥与密码写日志 | AI 初始化打印 key；NVS 凭据解析打印 password | 串口日志包含凭据；发布或分享前脱敏，后续移除日志 |
| PWR 事件没有消费者 | 只有 PWR 初始化与置位 | 不能承诺 PWR 软件休眠功能已实现 |
| 天气刷新为异步操作 | MCP 只设置事件位，后台任务执行 HTTP | 工具返回成功只代表请求提交，需等待实际刷屏；失败可再次语音请求 |
| 图片上限检查发生在解码后 | `EPD_SDcardScaleIMGShakingColor` | 超大源图仍可能先耗尽内存；应先读取头部做尺寸和容量检查 |

工程后续完善宜先处理配置/网络输入边界、屏幕锁和休眠竞争，再统一按键、刷新状态与错误反馈；否则即使功能入口齐全，异常输入和连续操作下仍可能不稳定。

## 20 手动天气与 Seedream 5.0 Flash 更新验收

本次变更取消开机天气请求，增加 `self.disp.refreshWeather`，配套模型改为 `doubao-seedream-5-0-flash-260915`。请求 1280×720 JPEG，复用设备原有的 800×480 缩放及六色抖动流程。16:9 到 5:3 沿用拉伸处理。

更新设备时，除固件外，将配套 `02_SDCARD/06_user_Foundation_img/config.txt` 复制到实际 SD 卡的同名位置。使用你自己的有效 API Key，并确保账号已开通该模型；如果卡上配置未更新，固件仍会读取旧模型。

建议上板检查以下操作：

1. 冷启动进入 AI 模式：应保留原画面，串口不应出现天气 HTTP 请求。
2. 说“刷新天气”：应提交后台请求，成功后显示天气；再次说同一句应允许再次刷新。
3. 天气接口访问失败或返回错误 JSON：不应清屏，恢复网络后可再次语音请求。
4. 说“生成一张月球图片”：应请求 5.0 Flash 的 1280×720 JPEG，下载后缩放和抖动显示。
5. 再检查本地图片切换、轮播与温湿度查询，确认原有工具仍然可用。

MCP 返回成功表示异步请求已提交，不表示网络请求和刷屏已经完成。上述硬件和云端验收尚需实际设备验证，本文编写过程未使用密钥调用付费生图接口。

编译验证：ESP-IDF 5.5.2 构建退出码 0，生成 `build/xiaozhi.bin`（3,983,872 字节，0x3cca00），通过应用分区容量检查，分区剩余约 4%。完整日志位于工程 `build/manual-weather-seedream-build.log`。


2026 年 10 月 19 日修正：Seedream 5.0 Flash 请求移除旧模型的组图参数及显式流式开关，避免 InvalidParameter HTTP 400。云端生成结果仍需上板验证。
